## Behavior Changes

### Before (Old Behavior)
```
Event → Pipeline → _have_all_fields check → FAIL → Log: "Fields incomplete" → SKIP
```

### After (New Behavior)
```
Event → Pipeline → route_and_execute → Log: "📤 [HANDOFF]" → 
Coordinator → Fail-open normalization → Execution attempt → Log: "📥 [HANDOFF]"
```

## Coordinator's Fail-Open Logic (Already Existed)

The coordinator in `execution_coordinator.py` already had robust fail-open logic:

1. **Amount Normalization:**
   - Missing/invalid → Use config default (0.001 SOL)
   - Log: "🔧 [FAIL-OPEN] Amount missing/invalid, using default: 0.001 SOL"

2. **Action Normalization:**
   - Missing → Default to 'buy'
   - Log: "🔧 [FAIL-OPEN] Action missing, defaulting to: buy"

3. **DEX Normalization:**
   - Unknown → Treat as 'unknown' and route intelligently
   - Log: "🔧 [FAIL-OPEN] DEX '...' not recognized, treating as 'unknown'"

4. **Route Selection:**
   - dex=="jupiter": Try Jupiter → direct_copy
   - dex=="meteora": Try Meteora → Jupiter → direct_copy
   - dex=="unknown" with mint: Try Jupiter → direct_copy
   - dex=="unknown" with signature: Try direct_copy (transaction cloning)

## Benefits

1. **Maximum Execution Coverage**
   - Every trade event is processed, not just complete ones
   - No opportunities missed due to incomplete data

2. **Intelligent Fallbacks**
   - Coordinator picks best execution path based on available data
   - Signature-only events can use direct_copy (transaction cloning)

3. **Better Observability**
   - Clear handoff markers in logs
   - Coordinator routing decisions always logged
   - Fail-open normalization visible in logs

4. **Fail-Open Design**
   - Missing fields trigger sensible defaults
   - System never halts execution due to incomplete data
   - Maximizes trading opportunities
